## 0. 验收标准与红线

**验收标准(拿下一个新品牌来检验)**:接入一个新品牌 = 填一份品牌档案 + 登一次 cookie,
**零个**新 .cjs 脚本、**零个**前端组件分支、**零处**手工编辑 crontab、巡检自动覆盖。

**红线(不做的事)**:
- 不重写、不动现有数据表结构(品牌档案走代码文件,无 Prisma 迁移)
- 不碰本机 21:30 拖滑块登录例程(唯一登录通道)
- 不重构特斯拉 partner/聚光等深度定制逻辑的**内部**,只在外面包一层配置判断
- 改 crontab 的每一步必须机器自动备份旧表,一条命令可回滚
- 每个 step 独立 commit,可单独 revert;上线窗口避开 21:00-06:00 数据高峰

## 3. Phase 1:品牌档案配置化(核心)

### Step 1.1 新建品牌档案层(纯增量,零风险)

新增 `backend/src/brand/brand-profiles.ts`(与前端 brands.js 对称):

```ts
export interface BrandProfile {
  brandId: number;
  name: string; short: string;
  channels: { spark: boolean; partner: boolean; pro: boolean; laigu: boolean };
  funnel: {
    caliber: 'note_pm' | 'clue_tool' | 'pro_clue';   // 漏斗口径(命名版本,口径留痕的锚点)
    since?: string;                                    // '2026-11-24' 切换日,审计用
    fallback?: 'note_pm';                              // clue 表空时回退(奕境现状的固化)
    advertiserFilter?: string;                         // MDD 10847045
    natureSubtract?: 'campaign';                       // 自然=总−聚光(MDD/奕境公式)
  };
  notes: {
    mode: 'rolling_backfill' | 'window30' | 'daily_partition';  // 2/5/7|8 三种同步模式
    noteSources?: string[];                            // 荣威['专业号笔记','员工笔记'] / MDD['员工笔记']
    autoRegisterAuthors?: boolean;                     // 荣威 true
    baselineOnly?: boolean;                            // MDD 基线账号
    excludeAuthors?: string[];                         // MDD MorganDaDa
    monitorScopeOnly?: boolean;                        // 格力监控账号(greeAuthorScope)
    masterDeprecated?: boolean;                        // 特斯拉 KoxNote 弃用
  };
  patrol: { inScope: boolean; coverThreshold?: number };
}
```

新增 `backend/src/brand/brand-profiles.service.ts`:`getProfile(brandId)`、`isFunnelCaliber(brandId, caliber, atDate?)`。
未配置品牌给安全默认值(通用行为,即现在的"无特判"路径)。

- **验证**:`tsc --noEmit`;不接任何调用点,纯新增文件。
- **回滚**:删文件即可,零影响。

### Step 1.2 后端分支改读档案(渐进,每处一个 commit)

按痛感排序,逐处替换,每处改完跑 Phase 0 快照 diff(必须逐字节一致,豁免字段除外):

| 顺序 | 位置 | 现状 | 改为 |
|---|---|---|---|
| a | `kox.service.ts` overview lead_funnel | `brandId === 7`(clue) / `!== 6`(note_pm) / brand6(pro_clue) | `profile.funnel` 驱动三选一 + fallback + since |
| b | `kox.service.ts` overview 品牌特判 | brand8 greeAuthorScope、brand6 noteRows 弃用 | `profile.notes.monitorScopeOnly / masterDeprecated` |
| c | `spark.service.ts` syncNotes | brand2 自动注册、brand5 baselineOnly/excludeAuthors/noteSources | profile.notes 字段 |
| d | `spark.service.ts` syncCampaign | brand5 advertiserFilter + 无日期连刷 3 天、brand6 partner_vseller 判断 | profile.campaign 字段(特斯拉只换判断来源,内部不动) |
| e | `spark.service.ts` safeSyncOrg | brand2 notes 滚动重拉分支 | profile.notes.mode === 'rolling_backfill' |
| f | `patrol.cjs` PIPELINE_BRANDS、口径相关检查 | 硬编码 [2,5,6,7,8] 与 2/8、5/7 | 读档案(脚本内联一份同样的 TS→JSON,或生成 `patrol-brands.json`) |

- **每步验证**:快照 diff 为空 + patrol 输出与 Phase 0 留档一致 + `tsc`。
- **回滚**:单 commit revert;出问题不影响数据(全部只读路径,唯一写路径 syncNotes 的分支替换要配 `trigger-sync notes 2/5/7` 各跑一次并 diff 入库行数)。

## 4. Phase 2:调度收敛

### Step 2.1 作业清单化(纯增量)

新增 `deploy/jobs.yaml`,把现存 4 处调度(backend safeSync 定时器、deploy crontab、root crontab、本机登录钩子)登记成一份清单:

```yaml
jobs:
  - { id: df-notes, schedule: "50 5 * * *", user: deploy, run: "cron-sync-brand-notes.sh 7",
      needs_cookie: [7], lock: df-notes-sync }
  - { id: df-values-refresh, schedule: "50 5,11,17 * * *", user: deploy, run: "cron-sync-note-values-refresh.sh 7" }
  - { id: patrol-morning, schedule: "20 8 * * *", user: root, run: "patrol.cjs --push" }
  - { id: pull-t1, trigger: on-login, notes: "本机 21:30 拖滑块后由登录钩子调用,不在 crontab" }
  # ...现存全部作业逐条登记(以服务器两份 crontab 为准,一条不漏)
```

配套 `tools/verify-cron.cjs`:ssh 不可用时人工贴入两份 crontab,与 jobs.yaml 比对输出漂移 diff。
**本步不改变任何执行路径**——先有"唯一事实清单",消除"改了 crontab 忘记另一处"这类事故。

### Step 2.2 crontab 生成器(改变执行路径,带自动备份)

新增 `deploy/install-crontab.sh`:从 jobs.yaml 生成 root/deploy 两份 crontab,安装前自动
`crontab -l -u <user> > deploy/crontab-backup-<user>-<ts>`,生成 diff 让操作者确认后写入。
此后**禁止手工编辑 crontab**,改动一律走 git → install-crontab.sh。

- **验证**:生成结果与当前线上 crontab `diff` 为空后(先做等价生成,不加作业),才算迁移完成。
- **回滚**:`crontab deploy/crontab-backup-<user>-<ts>` 一条命令恢复。

### Step 2.3 同品牌多脚本合并

- `cron-sync-{mdd,df}-notes.sh` → `cron-sync-brand-notes.sh <brandId>`(内部按 profile 决定跑
  notes/notes_daily/clue_analysis/clue_acq_tool 哪些槽位;奕境 11-24 已加的两槽位即成为配置的受益者)。
- `df-note-values-refresh.cjs` + `mdd-note-values-refresh.cjs` → `note-values-refresh.cjs --brand=N`
  (df 版里的封面写入/无标题回填逻辑保留,参数化品牌)。
- 旧脚本保留一个版本周期,crontab 切换后观察 2 天再删。

- **验证**:连续两天比对 SparkSyncLog 各 syncType 的成功行数与改前基线持平。
- **回滚**:crontab 备份恢复 + 旧脚本仍在。
