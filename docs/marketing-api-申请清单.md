# 聚光 Marketing API 申请清单与接口映射

> 目的：替换当前依赖浏览器会话（24 小时强制重认证）的聚光数据抓取链路。
> 结论先行：**数据报表 API 已全量开放给品牌方和代理商，但注册必须由小红书销售在内部系统发起**，
> 我方的工作是准备好资质包递给销售，并完成后续 OAuth2.0 技术对接。
> 官方文档: https://ad.xiaohongshu.com/openApiDoc?articleId=2777 (入门指南)
> 开发者文档: https://ad.xiaohongshu.com/developers/docs/guide (OAuth2.0/素材等)

## 一、申请路径（谁发起、找谁）

| 账户 | 走哪个销售渠道 | 备注 |
|---|---|---|
| 特斯拉（partner 通道, orgCode partner-agent-leyun-7883） | **乐允渠道的销售**（代理商主体发起） | 一份代理商开发者注册可覆盖名下子账户报表 |
| 荣威 / 东风 / 格力 MCC | 各品牌直客的小红书销售 | 每个账户主体一份授权 |

话术要点：申请开通「聚光开放平台 Marketing API - **数据报表**」（已全量）；
如后续要 API 创编投放，再谈「投放管理」（客资收集/产品种草，已全量，仅品牌方）。

## 二、申请材料清单（销售发起注册时需我方提供）

以官方《数据API注册及使用流程》为准，以下为标准包（★=必给）：

1. ★ 营业执照（每个账户主体一份：乐允、荣威主体、MDD、东风奕境、格力）
2. ★ 聚光账户标识：账户 ID / organization ID（已有：SparkOrgConfig 表各 brandId 的 orgCode）
3. ★ 技术对接人：姓名、手机、邮箱（用于接收授权信息和开发者账号）
4. ★ API 使用场景说明：申请「数据报表-账户报表/笔记报表」，用于品牌营销数据看板的自动化报表拉取；
   预估频率：每账户每日 ≤ 50 次调用、单次分页 ≤ 1000 行
5. ★ 服务器出口 IP 白名单：`119.28.157.150`（生产服务器；后续本地开发机按需追加）
6. OAuth2.0 回调地址：`https://<域名>/api/agency-api/marketing-api/oauth/callback`（上线前在 Nginx 加路由）
7. 代理商与品牌的授权关系证明（乐允↔特斯拉；如销售要求）
8. 蒲公英 API（博主报价等）如需：注意门槛为年流水 500 万+，特斯拉项目如达标可一并提

## 三、当前抓取链路 → Marketing API 映射

| 现有链路 | 现状痛点 | API 对应 | 覆盖度 |
|---|---|---|---|
| 4 品牌 MCC 投放日指标（rtb_metrics） | cookie 24h 必掉 | 数据报表-账户报表 | ✅ 完全覆盖（消耗/曝光/点击/互动） |
| MCC 笔记明细（vision target_detail_list） | 同上 | 数据报表-笔记报表 | ✅ 内容指标覆盖；员工维度字段需与销售确认 |
| MCC 员工矩阵（staff_detailList → SparkStaff*Daily） | 同上 | ⚠️ KOS/员工维度不在标准报表内 | 需销售确认；不覆盖则保留 cookie 链路做兜底 |
| 特斯拉 partner 盯盘主表（vsellerMonitor） | 24h 会话+滑块 | 代理商开发者授权后的子账户报表 | ✅ 大概率覆盖，申请时明确列出 |
| 聚光标准投笔记报表（leona note report） | Playwright+浏览器会话 | 数据报表-笔记报表（timeUnit=DAY） | ✅ 覆盖 |
| 聚光商业内容（creative_center noteList） | 同上 | 笔记报表/内容维度 | ✅ 大概率覆盖 |
| 专业号 KOS 员工明细（pro.xiaohongshu.com） | 24h 重认证 | ⚠️ 专业号侧不在聚光 Marketing API 范围 | 需单独咨询（专业号数据服务），短期走本地保活 |
| 专业号线索经营（clue pages） | 同上 | ⚠️ 客资类 API 与聚光"客资收集"投放管理绑定 | 需销售确认范围；短期走本地保活 |
| 来鼓评论/私信 | 来鼓 token（目前稳定） | 不适用 | 无需替换 |
| 小红书主站封面/头像 | 一次性脚本 | 不适用 | 无需替换 |

**结论**：API 落地后，10 条在管链路中约 7 条（含全部每天掉线的）可脱离浏览器会话；
专业号两条继续用「本地保活 + 每日 storageState 推送」方案，来鼓不动。

## 四、拿到授权后的技术接入（我方工作，预计 2~3 天）

1. OAuth2.0 授权回调路由 + token 存取表（MarketingApiConfig：accountId/token/过期时间）
2. 报表拉取客户端（对齐现有 SparkApiClient 结构），按日拉取 → 落现有同构表（KoxCampaignDailyStat 等）
3. 双跑期 ≥ 1 周：API 数据与旧抓取并行比对（消耗误差 < 1% 后切换）
4. 旧链路降级为兜底（cookie 失效不再告警）
